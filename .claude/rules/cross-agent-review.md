# Codex / ClaudeCode 相互レビュー

## 基本方針

記事を作成したエージェント自身だけで公開判断を完結しない。`articles/*.md` に新規記事を作成した後、または既存記事を公開前に大きく改稿した後は、公開前に Codex と ClaudeCode の相互レビューを通す。

目的は、宣伝寄り・説明不足・守秘リスク・技術的な誤解を片方の視点だけで見落とさないこと。

## 役割分担

| 作成者 | レビュー担当 | やること |
| --- | --- | --- |
| Codex | ClaudeCode | `CLAUDE_CODE_HANDOFF.md` と Skill Graph handoff にレビュー依頼を残す |
| ClaudeCode | Codex | `CLAUDE_CODE_HANDOFF.md` と Skill Graph handoff に Codex レビュー依頼を残す |
| ユーザー手動作成 | 直近で編集していない側を優先 | どちらがレビュー済みかを明記する |

同じエージェントが自己レビューする場合も、公開前チェックとしては有効だが、相互レビュー済みとは扱わない。

## レビュー依頼に必ず含める情報

- 対象ファイル: `articles/<slug>.md`
- 状態: `published: false`
- 作成者または主編集者
- レビュー観点
- 触ってよい範囲（原則は対象記事のみ）
- `published: true` はユーザーが明示するまで変更しないこと

## 共通レビュー観点

- 「課題 → 判断 → 実装 → 検証/使いどころ → まとめ」の流れが自然か
- 体験記事として成立しており、単なる機能紹介や網羅解説に寄りすぎていないか
- 技術説明に誤解を招く表現がないか
- GitHub リンク、5行以上の実コード、体験/失敗例、参考リンクが入っているか
- 文体ルール違反語、AI的な締め文、曖昧な主語がないか
- 守秘義務・個人情報・体調詳細・他社批判に触れていないか
- フロントマターの `topics` が5個以内で、`published: false` のままか

## 公開前ゲート

`published: true` に変更してよいのは、次を満たすときだけ。

1. 作成者側のセルフチェックまたは `/article-review` 相当が済んでいる
2. もう一方のエージェントによるレビュー依頼またはレビュー結果が記録されている
3. 重大指摘が残っていない
4. ユーザーが公開を明示している
