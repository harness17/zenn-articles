# テーマ選定方針

## 軸：課題解決力

**SQL Server チューニング等の知見深度が必要なテーマは無理に書かない。**
「実際に詰まって、自分で考えて、こう解決した」という体験ベースの記事を優先する。

Lapras 評価のためだけでなく、選考時に「思考プロセスを言語化できる人」と
評価される副次効果を狙う。

### この方針を満たす記事の特徴

- **詰まったポイントが明確**：「〇〇で動かなかった」「〇〇でクォータが枯渇した」
- **解決の判断軸が言語化されている**：「△△ではなく□□を選んだのは〜のため」
- **数字や仕様の出典がある**：「YouTube Data API のクォータは10,000ユニット/日」
- **再現コードが個人開発リポジトリにある**：DevNext / youtube-schedule / google-chrome-extensions

### この方針から外れる記事

- 「〇〇テクニック5選」のように網羅的な知見記事（書籍に勝てない）
- 体験を伴わない設計論（「〇〇パターンとは」のような解説記事）

### 🛠 候補N: Claude Code 導入から数ヶ月の運用変遷 — 何を入れて何を捨てたか

- **ソース**: 自分の `~/.claude/` 配下の rules / skills / settings.json の git history、運用ログ
- **書ける理由**: 単発レビュー記事と違い「**時系列で何を変えたか**」を語れる人は少ない／実証物（rules フォルダ・skill群）が手元にある
- **想定読者**: Claude Code を導入したが運用が固まらない個人開発者、複数 AI ツールを併用している層
- **想定文字数**: 3500〜4500字 / 想定執筆時間: 5〜6時間
- **障害情報リスク**: なし（候補L と違い純粋な技術ワークフロー記事）
- **章立て案**:
  1. **導入直後**：単一 CLAUDE.md・skill なし・worktree 未使用の素朴な状態
  2. **ハーネス細分化フェーズ**：CLAUDE.md フラット → `rules/` 分割 → `@import` 構造への移行と理由
  3. **Codex との使い分けフェーズ**：「実装は Codex に投げて Claude は設計とレビューに専念」の役割分担確立
  4. **advisor 戦略の導入**：Sonnet 実行 + Opus 助言の構造化（実コスト削減データがあれば追加）
  5. **スキルグラフ連携フェーズ**：My-Skill-Graph（Obsidian ボルト）に設計判断を自動登録する `skill-graph-auto-register.md` ルール化／**会話を超えた知識持続化**で「なぜこの技術を選んだか」が後から辿れる／フリーランス案件の信頼根拠・職経書ネタにも転用できる二次効果
  6. **トークン枯渇からの逆算**：`/loop` 廃止・skill 化による定型化など、上限から逆算して捨てたもの
- **NG切り口（書かない）**: 「Claude Code 入門」「skill とは何か」のような公式ドキュメント焼き直し
- **OK切り口（これだけ書く）**: 「導入時はこうしていた → こう詰まった → こう変えた」の **before / pain / after** 構造で時系列に並べる
- **強み**: 「トークン枯渇 → 効率化模索」という **痛み駆動の改善履歴**が固有価値（成功談だけの記事より刺さる）

### 🧱 候補M: DevNet と DevNext で同じ機能を別実装にした設計判断の差分

- **ソース**: DevNet（.NET Framework 版）／ DevNext（ASP.NET Core 10 版、218 commits）の CommonLibrary
- **書ける理由**: 個人で2世代分のテンプレートを保守している立場が希少／新旧で同じ抽象化を別形にした理由を一次情報で語れる
- **想定読者**: ASP.NET Core 系の共通基盤を設計する中堅エンジニア、レガシー .NET から移行を検討している層
- **想定文字数**: 3000〜4000字 / 想定執筆時間: 5〜6時間
- **障害情報リスク**: なし
- **NG切り口（書かない）**: 「CommonLibrary の作り方」「便利メソッド集」「DevNext 紹介」のような体験を伴わないチュートリアル系
- **OK切り口（これだけ書く）**: 「同じ要求を Framework 版で書いた実装を Core 版でこう変えた／こう捨てた」「Generic を入れすぎて読めなくなった失敗」「3年使い回した自前ライブラリで後から後悔した抽象化」のような **差分・後悔ベース**
