# テーマ選定方針

## 軸：課題解決力

**SQL Server チューニング等の知見深度が必要なテーマは無理に書かない。**
「実際に詰まって、自分で考えて、こう解決した」という体験ベースの記事を優先する。

Lapras 評価のためだけでなく、選考時に「思考プロセスを言語化できる人」と
評価される副次効果を狙う。

### この方針を満たす記事の特徴

- **詰まったポイントが明確**：「〇〇で動かなかった」「〇〇でクォータが枯渇した」
- **解決の判断軸が言語化されている**：「△△ではなく□□を選んだのは〜のため」
- **数字や仕様の出典がある**：「YouTube Data API のクォータは10,000ユニット/日」
- **再現コードが個人開発リポジトリにある**：DevNext / youtube-schedule / google-chrome-extensions

### この方針から外れる記事

- 「〇〇テクニック5選」のように網羅的な知見記事（書籍に勝てない）
- 体験を伴わない設計論（「〇〇パターンとは」のような解説記事）
