# 記事の必須要素・推奨構成

## 各記事に必須で含める要素

| 要素 | 理由 |
|------|------|
| GitHub リポジトリへのリンク | Lapras GitHub スコアと連動する |
| 実コード（5行以上） | 検証可能性を上げる |
| 自分の体験・失敗例 | 一次情報としての価値 |
| トピックタグ（5個以内） | 検索性、Lapras 認識率 |

## 推奨文字数

- 通常記事：**2500〜4000字**
- 軽め記事：1500〜2500字（数を稼ぐ用途）

## Zenn記事テンプレート

```markdown
---
title: ""
emoji: "🔧"
type: "tech"
topics: []
published: false
---

## はじめに（200〜300字）
- 何の記事か
- 誰に読んでほしいか
- 何が分かるか

## 本論（メイン3〜5セクション）
- 各セクション = 見出し + 具体例（コード or 図） + 解説
- コードブロックは必ず言語指定する（` ```sql ` ` ```csharp `）

## まとめ（150〜250字）
- 要点3つ
- 次に読んでほしい記事への誘導（あれば）

## 参考リンク
- 公式ドキュメント
- 関連リポジトリ（DevNext など）
- 参考にした記事
```

## 個人開発リポジトリの言及

ユーザー方針：**積極的に言及して良い**。

- 抽象的説明には「実例として DevNext では〜」と具体例を添える
- 記事末尾の「参考リンク」に該当リポジトリを必ず載せる
- ASP.NET Core 10 系の記事は特に DevNext との接続を意識する
